# Техническое задание и план развития

## Проект «Инвентаризация объекта» для Getac V110

**Версия:** 0.1 (черновик для согласования)  
**Дата:** 04.11.2026  
**Статус:** на согласовании, код не изменяется до утверждения  
**Основание:** подготовить Getac V110 к инвентаризации объекта с большим количеством камер, коммутаторов и другого оборудования.

---

## 1. Общие сведения

### 1.1. Назначение

Приложение должно стать рабочим местом инспектора для полевой инвентаризации оборудования на объекте: камер, коммутаторов, видеорегистраторов, точек доступа, ИБП, патч-панелей и другого сетевого/слабoточного оборудования.

### 1.2. Ключевая идея

Инспектор работает в перчатках, с сенсорным экраном, в неудобных условиях (шкафы, потолки, серверные). Поэтому основной сценарий должен быть предельно коротким:

**выбрал тип и локацию → сканировал код → устройство сохранено → перешёл к следующему.**

Все остальные поля (модель, IP, питание, примечание, фото) заполняются по возможности или позже. Приложение не должно заставлять заполнять длинную форму перед каждым сканом.

### 1.3. Среда эксплуатации

- Ноутбук Getac V110, Windows 10/11 64-bit.
- Сенсорный экран, разрешение от 1366×768.
- Встроенный сканер штрихкодов (COM-порт или режим клавиатуры).
- Встроенный микрофон, при наличии — камера.
- Работа полностью офлайн; интернет не требуется.
- Опционально: локальный Ollama на ноутбуке.
- Один инспектор, одна активная сессия на устройстве.

## 2. Цель и задачи

### 2.1. Цель

Сократить время обхода и исключить ручное переписывание данных: инспектор сканирует оборудование, приложение само раскладывает данные по полям, наследует локацию, проверяет дубли и в конце формирует готовый Excel-отчёт.

### 2.2. Задачи

1. Убрать зависимость от LLM из критического пути: базовый разбор кодов должен быть мгновенным и локальным.
2. Ввести контекст обхода: объект → здание → этаж → помещение → шкаф → юнит.
3. Разделить тип данных (MAC/серийник/EAN) и тип оборудования (камера/коммутатор/регистратор).
4. Сделать надёжное хранилище: SQLite как рабочая база, Excel — как отчёт.
5. Довести голосовой ввод до рабочего состояния: заметка должна попадать в активное устройство.
6. Добавить проверку дублей, редактирование, поиск и восстановление после сбоя.
7. Добавить предстартовую проверку готовности ноутбука.
8. Сформировать Excel-отчёт с устройствами, связями, сводкой и проблемными позициями.

### 2.3. Показатели успеха

| Показатель | Целевое значение |
|---|---|
| Время от скана до сохранения (быстрый режим) | ≤ 1 секунды |
| Доля устройств с типом и локацией | 100% |
| Доля устройств с S/N, MAC или пометкой «без маркировки» | ≥ 95% |
| Потеря данных при аварийном выключении | 0 записей |
| Работа без Ollama | Полная функциональность |
| Подготовка отчёта в конце смены | ≤ 1 минуты |
| Обход 100 устройств без сбоев | Успешно |

## 3. Границы проекта

### 3.1. Входит в объём

- Работа на одном Getac V110.
- Сессии инвентаризации и архив сессий.
- Локации и наследование текущей локации.
- Сканирование: COM-порт, режим клавиатуры (HID), ручной ввод.
- Локальный разбор MAC, серийных номеров, EAN, IP, структурированных QR.
- Карточка устройства и быстрый режим.
- Голосовые заметки.
- Фото устройства/этикетки (опционально).
- Проверка дублей по S/N и MAC.
- Связи «устройство → вышестоящее устройство / порт».
- Предстартовая проверка.
- SQLite-хранилище, резервные копии, журнал.
- Экспорт в Excel.
- Настройки и журнал ошибок.
- Полевая инструкция.

### 3.2. Не входит в MVP

- Автоматическое обнаружение устройств в сети (ONVIF, LLDP, ping-сканирование).
- Синхронизация с сервером, облаком, 1С и другими системами.
- Печать этикеток.
- Карты помещений и схемы.
- Одновременная работа нескольких инспекторов.
- Мобильное приложение для телефона.
- Автоматическое распознавание модели по фото.
- Полный порт-уровневый учёт патч-панелей (в MVP порт — текстовое поле).
- Сравнение с предыдущей инвентаризацией (перспектива).
- PDF-отчёты (перспектива).

### 3.3. Допущения

- На оборудовании есть этикетки хотя бы с одним идентификатором: S/N, MAC, EAN/QR.
- Сканер Getac можно настроить в COM-режим или режим клавиатуры.
- Vosk-модель подходит для русского языка, но в шумном помещении возможны ошибки; текст всегда можно отредактировать.
- Ollama не обязательна и может быть отключена.
- Заказчика устраивает Excel как итоговый формат.
- Фото не является обязательным для каждой единицы.

## 5. Текущее состояние и разрывы

| Узел | Что уже есть | Проблема | Решение в новой версии |
|---|---|---|---|
| Интерфейс | Сенсорные кнопки, лог, крупные элементы | Кнопка «СТОП» не подключена; нет типа устройства и локации; интерфейс не ведёт по сценарию обхода | Экран обхода с контекстом, типами, карточкой и счётчиками |
| Сканер | Чтение COM3, звуковой сигнал, кнопка лазера | Порт зашит в код; нет переподключения и теста; режим HID не поддержан | Настраиваемый COM/HID/ручной режим, автопереподключение, тест |
| ИИ | Ollama, классификация строки | Запрос до 10 с блокирует UI; тип данных путается с типом оборудования; модель coder не для русского текста | Локальный парсер; ИИ — только опциональная подсказка |
| Голос | Vosk, запись с микрофона | Остановка не работает; текст пишется в последнюю строку | Заметка в активное устройство, редактирование, статус записи |
| Хранилище | Excel, автосохранение | Блокировки файла, копии при каждом сохранении, нет целостности и дублей | SQLite + экспорт в Excel по завершении |
| Отчёт | Сырой Excel | Нет сводки, связей, проблемных позиций | Многолистовой Excel-отчёт |
| Восстановление | Нет | Сбой/выключение может оставить неясное состояние | WAL, автобэкап, продолжение сессии |

| Роль | Возможности |
|---|---|
| Инспектор | Создаёт/продолжает сессию, сканирует, редактирует, добавляет голос/фото, завершает обход |

## 7. Пользовательские сценарии

### 7.1. Подготовка к обходу

1. Инспектор включает ноутбук и запускает приложение.
2. Приложение предлагает продолжить активную сессию или создать новую.
3. Инспектор указывает объект, ФИО, дату.
4. Открывается экран предстартовой проверки.
5. Проверяются батарея, диск, база, Vosk-модель, микрофон, сканер, камера, Ollama (опционально).
6. Инспектор выбирает локацию: здание, этаж, помещение, шкаф.
7. Нажимает «Начать обход».

### 7.2. Быстрый обход помещения

1. Инспектор выбирает тип оборудования крупной кнопкой, например «Камера».
2. Нажимает «Лазер» или аппаратную кнопку сканера.
3. Сканирует этикетку устройства.
4. Приложение мгновенно разбирает код:
   - MAC → в поле MAC;
   - серийный номер → в поле S/N;
   - EAN → в поле «Код сканирования» с пометкой «товарный код», не в S/N;
   - структурированный QR → несколько полей сразу.
5. Создаётся запись `CAM-012` с текущей локацией и типом «Камера».
6. Звучит подтверждение, счётчик увеличивается.
7. Инспектор переходит к следующему устройству.

### 7.3. Подробный режим

1. Инспектор сканирует код.
2. Открывается карточка с заполненными полями.
3. Проверяет тип, модель, S/N, MAC, IP, питание, статус.
4. Добавляет голосовую заметку и/или фото.
5. Сохраняет.
6. Приложение возвращается на экран обхода.

### 7.4. Устройство без этикетки

1. Инспектор нажимает «Добавить вручную».
2. Выбирает тип и локацию.
3. Приложение присваивает следующий ID.
4. Инспектор заполняет модель/примечание, ставит статус «Без маркировки».
5. Сохраняет.

### 7.5. Голосовая заметка

1. Инспектор выбирает активное устройство (последнее добавленное или из списка).
2. Нажимает и удерживает «Микрофон» (или кнопку на экране).
3. Говорит: «Камера у входа, объектив направлен на дверь, крепление на кирпич».
4. Отпускает кнопку.
5. Vosk распознаёт текст, приложение показывает его в поле заметки.
6. Инспектор при необходимости исправляет текст и сохраняет.

### 7.6. Фото

1. В карточке устройства инспектор нажимает «Фото».
2. Приложение делает снимок с встроенной/внешней камеры.
3. Снимок сохраняется в `data/photos/<uuid>.jpg` и привязывается к устройству.
4. В Excel экспортируется путь и, при необходимости, вкладка с фото.

### 7.7. Связывание с портом

1. Инспектор открывает карточку камеры.
2. Нажимает «Подключено к».
3. Выбирает вышестоящий коммутатор из списка или сканирует его код.
4. Указывает порт, например `Gi0/12`, тип кабеля.
5. Сохраняет связь.
6. В сводке видно количество устройств без связи.

### 7.8. Завершение обхода

1. Инспектор нажимает «Завершить сессию».
2. Приложение показывает сводку: всего устройств, по типам, по локациям, дубли, без S/N/MAC, без фото, без связи.
3. Инспектор исправляет критичные замечания.
4. Нажимает «Экспорт Excel».
5. Приложение формирует файл и открывает папку с ним.
6. Сессия переводится в статус «Завершена», создаётся резервная копия.

### 7.9. Возобновление после сбоя

1. Приложение аварийно закрылось или ноутбук выключился.
2. При следующем запуске приложение видит активную сессию.
3. Предлагает «Продолжить» или «Завершить».
4. Восстанавливает последнюю локацию, тип и активное устройство.
5. Данные не теряются, потому что каждая запись сохраняется отдельной транзакцией.

### 7.10. Поиск и исправление

1. Инспектор открывает «Список устройств».
2. Ищет по ID, S/N, MAC, IP, модели или примечанию.
3. Фильтрует по типу, локации, статусу, наличию фото/связи.
4. Открывает карточку, исправляет данные, сохраняет.
5. Удаление — только с подтверждением и записью в журнал.

## 8. Функциональные требования

### 8.1. Сессии

- **FR-01. Создание сессии.** Пользователь указывает объект, инспектора, дату; система создаёт сессию и делает её активной.  
  *Приёмка:* сессия сохраняется после перезапуска приложения.
- **FR-02. Продолжение сессии.** При наличии активной сессии приложение предлагает продолжить её.  
  *Приёмка:* восстанавливаются локация, тип и счётчики.
- **FR-03. Завершение сессии.** Сессия переводится в статус «Завершена», создаётся резервная копия.  
  *Приёмка:* завершённую сессию нельзя случайно изменить без подтверждения.
- **FR-04. Архив сессий.** Список прошлых сессий с датой, объектом, количеством устройств и экспортом.  
  *Приёмка:* можно открыть архивную сессию только для чтения.
- **FR-05. Одна активная сессия.** Нельзя создать новую сессию, не завершив текущую.  
  *Приёмка:* при попытке появляется диалог завершения/архивации.

### 8.2. Локации

- **FR-06. Иерархия локаций.** Здание → этаж → помещение → шкаф → юнит. Поля, кроме этажа/помещения, могут быть пустыми.  
  *Приёмка:* локация сохраняется и отображается в карточке и Excel.
- **FR-07. Наследование локации.** Все новые устройства получают текущую локацию без повторного ввода.  
  *Приёмка:* после смены локации новые записи получают новую, старые не меняются.
- **FR-08. Быстрый выбор локации.** Список недавних локаций и кнопки «Следующее помещение», «Следующий шкаф».  
  *Приёмка:* смена локации — не более 2 нажатий.
- **FR-09. Редактирование локации.** Можно изменить локацию устройства после сохранения.  
  *Приёмка:* изменение отражается в БД и экспорте.

### 8.3. Сканирование

- **FR-10. Режимы ввода.** COM-порт, режим клавиатуры (HID), ручной ввод.  
  *Приёмка:* все три режима работают на Getac.
- **FR-11. Настройка COM.** Порт, скорость, биты, чётность, кодировка, префикс/суффикс.  
  *Приёмка:* настройки сохраняются между запусками.
- **FR-12. Автопереподключение.** При потере порта приложение пытается переподключиться и показывает статус.  
  *Приёмка:* после отключения/подключения сканера сканирование восстанавливается без перезапуска.
- **FR-13. Тест сканера.** Экран показывает последний сырой код и результат разбора.  
  *Приёмка:* тест доступен до начала обхода.
- **FR-14. Кнопка лазера.** Настраиваемая последовательность клавиш; по умолчанию F11/F12.  
  *Приёмка:* кнопка на экране активирует сканер на тестовом Getac.
- **FR-15. Защита от дребезга.** Повторный тот же код в течение 1 секунды игнорируется.  
  *Приёмка:* двойной скан не создаёт две записи.
- **FR-16. Ручной ввод.** Диалог ввода кода с клавиатуры/экранной клавиатуры.  
  *Приёмка:* код проходит тот же парсер, что и сканер.

### 8.4. Разбор кодов

- **FR-17. MAC.** Поддержка 12 hex-символов, разделителей `:`, `-`, `.`; нормализация к виду `AA:BB:CC:DD:EE:FF`.  
  *Приёмка:* тесты на 10 вариантах.
- **FR-18. EAN/UPC.** 8/12/13/14 цифр с проверкой контрольной суммы; классификация как «товарный код», не S/N.  
  *Приёмка:* валидный EAN не попадает в S/N.
- **FR-19. Серийный номер.** Буквенно-цифровая строка 5–32 символа, минимум одна буква и одна цифра; исключения для MAC/EAN.  
  *Приёмка:* типовые S/N Hikvision, Dahua, Cisco распознаются.
- **FR-20. Структурированный QR.** Разбор пар `SN=`, `S/N=`, `MAC=`, `IP=`, `MODEL=`; заполнение нескольких полей.  
  *Приёмка:* QR с несколькими полями заполняет карточку.
- **FR-21. IP-адрес.** Проверка корректности IPv4.  
  *Приёмка:* некорректный IP не сохраняется без подтверждения.
- **FR-22. Неизвестный код.** Не блокирует работу: создаётся запись с пометкой «Требует проверки».  
  *Приёмка:* неизвестный код можно сохранить и исправить позже.
- **FR-23. Приоритет типов.** При неоднозначности приложение показывает предположение и позволяет сменить тип вручную.  
  *Приёмка:* 12 hex символов можно трактовать и как MAC, и как S/N.

### 8.5. Карточка устройства

- **FR-24. Поля карточки.** ID, тип, подтип, производитель, модель, S/N, MAC, IP, локация, питание, статус, примечание, фото, связь, код сканирования, тип кода.  
  *Приёмка:* все поля сохраняются и экспортируются.
- **FR-25. Обязательные поля.** Тип и локация обязательны; остальные — рекомендуемые с предупреждением.  
  *Приёмка:* без типа/локации сохранить нельзя.
- **FR-26. Типы оборудования.** Камера, коммутатор, видеорегистратор, маршрутизатор, точка доступа, ИБП, блок питания, патч-панель, сервер, рабочая станция, прочее.  
  *Приёмка:* тип выбирается одной кнопкой, префикс ID соответствует типу.
- **FR-27. Статусы.** Установлено, не работает, требует замены, резерв, не найдено, демонтировано.  
  *Приёмка:* статус отображается цветом и попадает в сводку.
- **FR-28. Редактирование.** Любое поле можно изменить после сохранения.  
  *Приёмка:* изменения фиксируются в журнале.
- **FR-29. Удаление.** Только с подтверждением; запись остаётся в журнале.  
  *Приёмка:* случайное удаление невозможно.
- **FR-30. Активное устройство.** Приложение явно показывает, к какому устройству относятся голос, фото и связь.  
  *Приёмка:* заметка не попадает в чужую запись.

### 8.6. Дубли

- **FR-31. Проверка дублей.** При сохранении сравниваются нормализованные S/N и MAC в рамках сессии.  
  *Приёмка:* дубль не сохраняется без решения пользователя.
- **FR-32. Диалог дубля.** Показать существующую запись, различия и варианты: открыть существующую, обновить, добавить как новую с причиной, отмена.  
  *Приёмка:* все варианты работают.
- **FR-33. EAN не считается дублем устройства.** Повтор EAN — информационное предупреждение.  
  *Приёмка:* две камеры одной модели с одинаковым EAN можно сохранить.

### 8.7. Голос

- **FR-34. Запись.** Кнопка «Микрофон» с индикацией записи, таймером и уровнем сигнала.  
  *Приёмка:* запись стартует и останавливается по нажатию.
- **FR-35. Распознавание.** Vosk, русский язык; текст появляется в редактируемом поле.  
  *Приёмка:* фраза из 5–10 слов распознаётся и её можно исправить.
- **FR-36. Привязка к активному устройству.** Текст сохраняется в примечание выбранного устройства.  
  *Приёмка:* после смены устройства заметка не уходит в предыдущее.
- **FR-37. Статус голоса.** Экран показывает, загружена ли модель, доступен ли микрофон, идёт ли запись.  
  *Приёмка:* при отсутствии модели голос отключается с понятным сообщением, приложение работает.
- **FR-38. Словарь терминов.** Автозамена типовых ошибок: «камутатор» → «коммутатор», «регистратор» и т.п.  
  *Приёмка:* словарь настраивается в файле и применяется после распознавания.
- **FR-39. Повтор записи.** Можно перезаписать заметку, не теряя предыдущий текст.  
  *Приёмка:* есть кнопки «Отменить» и «Записать заново».

### 8.8. Фото

- **FR-40. Съёмка.** Снимок с встроенной или внешней камеры.  
  *Приёмка:* фото сохраняется и отображается в карточке.
- **FR-41. Хранение.** Файлы в `data/photos/`, имя — UUID устройства; сжатие до 1280 px по длинной стороне, JPEG 80%.  
  *Приёмка:* 1000 фото занимают разумный объём.
- **FR-42. Экспорт.** В Excel — путь к файлу; опционально вкладка с встроенными уменьшенными фото.  
  *Приёмка:* пути корректны, файлы открываются.

### 8.9. Связи

- **FR-43. Вышестоящее устройство.** Можно выбрать из списка или отсканировать.  
  *Приёмка:* связь сохраняется и отображается в обеих карточках.
- **FR-44. Порт.** Текстовое поле с подсказками форматов `Gi0/1`, `Port 24`, `U12`.  
  *Приёмка:* порт сохраняется и экспортируется.
- **FR-45. Список несвязанных.** Сводка показывает устройства без вышестоящего устройства.  
  *Приёмка:* можно быстро перейти к ним и заполнить.

### 8.10. Предстартовая проверка

- **FR-46. Проверки.** Батарея, диск, запись в БД, Vosk-модель, микрофон, сканер, камера, Ollama (опционально), дата/время.  
  *Приёмка:* каждая проверка имеет статус «OK / предупреждение / ошибка».
- **FR-47. Блокировка.** Без записи в БД или при критически низком заряде обход не начинается.  
  *Приёмка:* кнопка «Начать обход» блокируется с объяснением.
- **FR-48. Протокол проверки.** Результат сохраняется в журнал сессии.  
  *Приёмка:* можно посмотреть, что проверялось и когда.

### 8.11. Экспорт

- **FR-49. Excel.** Листы «Устройства», «Связи», «Сводка», «Проблемы».  
  *Приёмка:* файл открывается в Excel без ошибок.
- **FR-50. Форматирование.** Заголовки, жирный шрифт, фильтры, закрепление строки, ширины колонок, даты.  
  *Приёмка:* таблица читаема без ручной правки.
- **FR-51. Занятый файл.** Если файл открыт, экспорт пишется в копию с меткой времени и показывает путь.  
  *Приёмка:* данные не теряются.
- **FR-52. Резервная копия.** Перед экспортом создаётся копия БД.  
  *Приёмка:* копия восстанавливается.
- **FR-53. CSV/JSON (опционально).** Экспорт для обмена с другими системами.  
  *Приёмка:* данные совпадают с Excel.

### 8.12. Настройки

- **FR-54. Сканер.** Режим, порт, скорость, кодировка, клавиши лазера.  
  *Приёмка:* настройки применяются без перезапуска.
- **FR-55. Голос.** Устройство ввода, модель, порог тишины, словарь.  
  *Приёмка:* можно выбрать микрофон.
- **FR-56. ИИ.** Включение, URL, модель, таймаут. По умолчанию выключен.  
  *Приёмка:* при выключенном ИИ приложение работает полностью.
- **FR-57. Данные.** Папка данных, автобэкап, очистка старых копий, экспорт журнала.  
  *Приёмка:* пути настраиваются, старые копии не удаляются без подтверждения.

### 8.13. Журнал и восстановление

- **FR-58. Журнал.** Все сканы, создания, изменения, удаления, экспорт, ошибки.  
  *Приёмка:* журнал можно просмотреть и выгрузить.
- **FR-59. Автобэкап.** При старте/завершении сессии и раз в день; хранить последние 30 копий.  
  *Приёмка:* копии создаются автоматически.
- **FR-60. Восстановление.** Из резервной копии через меню настроек.  
  *Приёмка:* данные восстанавливаются, приложение запускается.
- **FR-61. Миграции.** Версия схемы БД и автоматическое обновление при запуске.  
  *Приёмка:* старая база открывается без потери данных.

### 8.14. Поиск и сводка

- **FR-62. Поиск.** По ID, S/N, MAC, IP, модели, примечанию.  
  *Приёмка:* поиск находит за ≤ 1 секунду на 10 000 записей.
- **FR-63. Фильтры.** Тип, локация, статус, наличие фото/связи, проверено.  
  *Приёмка:* фильтры комбинируются.
- **FR-64. Сводка.** Всего, по типам, по локациям, по статусам, дубли, без S/N/MAC, без связи, без фото.  
  *Приёмка:* цифры совпадают с выборкой.

## 10. Интерфейс

### 10.1. Экранная карта

1. Старт / выбор сессии.
2. Подготовка и предстартовая проверка.
3. Обход (главный экран).
4. Карточка устройства.
5. Выбор локации.
6. Список и поиск.
7. Связи.
8. Завершение и экспорт.
9. Настройки.
10. Журнал и восстановление.

### 10.2. Требования к UI

- Русский язык, крупные подписи.
- Минимальный размер сенсорной кнопки — 56×56 px, основной — 72+ px.
- Высокий контраст, тёмная тема допустима.
- Никаких мелких иконок без подписи.
- Опасные действия — с подтверждением.
- Всегда виден статус: сессия, локация, тип, счётчик, батарея, сканер, микрофон.
- Ошибки — человеческим языком, с действием («Проверить порт», «Повторить»).

### 11.3. Потоки и отзывчивость

- Главный поток — только UI.
- `ScannerThread` — чтение порта, сигналы в UI, корректная остановка при закрытии.
- `VoiceThread` — запись и распознавание, сигналы в UI.
- `AIWorker` — отдельный поток, таймаут 3–5 с, результат не блокирует сохранение.
- `ExportWorker` — экспорт с прогрессом.
- Любая операция длиннее 100 мс — вне главного потока.
- Запись в SQLite — короткими транзакциями в главном потоке; экспорт и бэкап — в фоне.

### 11.4. Конфигурация и журналы

- `config.json` — настройки сканера, голоса, ИИ, путей, UI.
- Значения по умолчанию — в коде; файл создаётся при первом запуске.
- `data/logs/app.log` — ротация 5×5 МБ.
- В журнал писать: запуск, смену настроек, ошибки, экспорт, восстановление.
- Сырые коды сканирования хранить в `scan_events`; в текстовый лог — по настройке (конфиденциальность).

### 11.5. Сборка и запуск

- Режим разработки: `python main.py`.
- Портативная сборка: PyInstaller one-folder, папка `model/` и `data/` рядом с `.exe`.
- Ярлык на рабочем столе Getac.
- Проверка запуска на чистой Windows 10/11 без Python.

## 12. Нефункциональные требования

- **NFR-01. Офлайн.** Все основные функции работают без интернета. Ollama — опция.
- **NFR-02. Производительность.** Разбор кода ≤ 50 мс, сохранение ≤ 200 мс, отклик UI ≤ 100 мс, поиск по 10 000 записей ≤ 1 с.
- **NFR-03. Надёжность.** WAL, транзакции, автобэкап, восстановление после аварийного выключения.
- **NFR-04. Удобство.** Управление одной рукой в перчатке, крупные кнопки, минимум вложенных меню.
- **NFR-05. Совместимость.** Windows 10/11 64-bit, Getac V110, разрешение от 1366×768.
- **NFR-06. Безопасность.** Данные только локально; опциональный PIN на настройки; журнал действий.

### 14.1. Порядок работ

1. Сначала — данные и парсер, потому что от них зависит всё остальное.

4. Связи и экспорт — после того, как основной поток данных стабилен.

## 15. Критерии приёмки проекта

Проект считается принятым, если на реальном Getac V110 выполнены все пункты:

1. Предстартовая проверка корректно определяет батарею, диск, БД, микрофон, Vosk, сканер.
2. Создаётся новая сессия, указывается объект и инспектор.
3. Локация выбирается и наследуется всеми новыми устройствами.
4. Сканирование работает в COM-режиме; после отключения/подключения восстанавливается.
5. Скан MAC, S/N, EAN и структурированного QR разбирается корректно.
6. EAN не попадает в S/N.
7. Быстрый режим: скан → запись ≤ 1 с, без открытия карточки.
8. Дубль по S/N или MAC не создаётся без решения пользователя.
9. Голосовая заметка сохраняется в активное устройство и редактируется.
10. Фото сохраняется и привязывается к устройству.
11. Связь с вышестоящим устройством и портом сохраняется.
12. Поиск и фильтры находят записи.
13. При аварийном завершении данные не теряются, сессия продолжается.
14. Экспорт Excel содержит устройства, связи, сводку и проблемы; открывается без ошибок.
15. Приложение работает без Ollama и без интернета.
16. Обход 100 устройств проходит без сбоев и потери данных.
17. Время работы от батареи — не менее 4 часов в режиме обхода.
18. Сборка запускается на чистой Windows без Python.
19. Есть полевая инструкция и резервная копия базы.
20. Журнал содержит действия и ошибки, достаточные для разбора инцидента.

## 19. Регламент полевого обхода (кратко)

Полная версия — в `field_survey_reglement.md`.

1. **До выезда:** зарядить батарею, проверить сканер, микрофон, модель, свободное место, дату/время, сделать бэкап.
2. **Старт:** создать сессию, указать объект и инспектора, пройти preflight, выбрать первую локацию.
3. **В помещении:** выбрать тип оборудования, сканировать устройства, контролировать счётчик и дубли.
4. **Исключения:** устройство без этикетки — добавить вручную; неизвестный код — сохранить с пометкой; дефект — статус и голосовая заметка.
5. **Переход:** сменить локацию, проверить количество устройств в помещении.
6. **Связи:** для камер/точек доступа указать коммутатор и порт; для коммутаторов — uplink.
7. **Завершение:** проверить сводку и «Проблемы», исправить критичное, экспортировать Excel, сделать бэкап, закрыть сессию.
8. **Правила:** одна единица — одна запись; EAN не считать серийным номером; не редактировать рабочий Excel вручную; все изменения — через приложение.

## Приложение B. Правила разбора кодов

1. Удалить управляющие символы, пробелы по краям, префиксы/суффиксы сканера.
2. **MAC:** 12 hex-символов, возможно с `:`, `-`, `.`; нормализовать в `AA:BB:CC:DD:EE:FF`.
3. **EAN/UPC:** 8, 12, 13 или 14 цифр; проверить контрольную сумму; не писать в S/N.
4. **S/N:** 5–32 символа, буквы и цифры, допускаются `-`, `_`, `/`; не MAC и не EAN.
5. **IP:** корректный IPv4.
6. **QR:** если есть `SN=`, `S/N=`, `MAC=`, `IP=`, `MODEL=` — разобрать пары и заполнить поля.
7. **Неизвестно:** сохранить как `unknown`, пометить «Требует проверки».
8. **Неоднозначность:** показать предположение и дать выбрать тип вручную.
